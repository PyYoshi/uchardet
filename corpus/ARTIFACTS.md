# 単一生成物の公開と再実行

`artifact.write_idempotent` は実験 model / 契約 C++ table / sequence 診断 report の
保存に使います。corpus ディレクトリ全体の transaction / 再開機能ではありません。

1. 同じ byte の既存出力は書き直さない。mtime も維持する。
2. 異なる既存出力はエラーにし、上書きしない。
3. 出力先と同じディレクトリの一意な一時ファイルへ全 byte を保存し、flush / fsync / close する。
4. hard link の排他的作成で完成したファイルだけを最終名へ公開する。
5. 自分が作った一時ファイルだけを除去する。

同時に同じ生成物を公開しても同じ結果に収束します。異なる生成物の場合は先に
公開したものを残し、後続は失敗します。途中例外の場合は最終名の部分ファイルを残さず、
同じコマンドを再実行できます。hard link 非対応 filesystem では失敗し、直接書込みへ
fallback しません。ローカルの hard link 対応 filesystem を使ってください。

強制終了・OS停止では一時ファイルが残る可能性があります。他プロセスの作業を消さないよう
自動 sweep はしません。再実行は一意な別一時ファイルを使います。電源断時の directory
永続化や分散filesystemの一貫性、未信頼ディレクトリへの書込みを保証するものではありません。
この改善は Python の生成物保存だけであり、P01 の native 安全性検証とは別です。

既に古い実装が残した不完全な最終ファイルは、内容不一致として保護します。
別の出力先で再生成して比較し、必要なら人手で古いファイルを退避してください。

training の依存 hash にこの helper を追加します。学習アルゴリズムは変わりませんが、
source hash が変わるため新しく生成する artifact / provenance の hash は変わります。
古い artifact は作成時の固定 commit で検証するか、同じ source manifest から新しい名前で
再生成します。validator の依存 hash 照合を無効化して旧生成物を受け入れてはいけません。

テストは途中例外、link非対応、同一／異なる内容の同時公開、再実行、既存ファイル保護を
人工 byte 列で確認します。さらに、実際の子Pythonプロセスをhard link公開の直前・直後で
同期して強制停止し、最終名が未作成または完全な内容であること、再実行の成功、
残留一時ファイルと異なる既存出力の保護を検証します。停止はテスト自身が起動した子だけが対象です。
これは公開境界のprocess kill検証であり、書込み途中の全命令位置、OS停止、電源断、
directoryの永続化、分散filesystem、生成pipeline全体の再開を検証したものではありません。
